Start Experimenting with M365 Copilot

New here? You’re in the right place. Your AI assistant does the heavy lifting — it sets up the project so you can jump straight into shaping your own design experiments on the One Copilot Shell. No setup experience required.

Prerequisites
Node.js — v18 or later. Download here
A code editor with an AI assistant — e.g. VS Code with GitHub Copilot, or Claude Code
Getting started
1
Set up and preview Open your IDE and AI assistant (VS Code + Copilot, Claude Code — whatever you like), then paste the prompt below. That’s the entire setup: your agent clones the repo, learns the project’s conventions, installs and builds everything, and opens the playground for you. It only takes a couple of minutes.
"Clone https://github.com/m365-core/bebop-playground.git and open it. First read the agent instructions — CLAUDE.md, .github/copilot-instructions.md, CONTRIBUTING.md, README.md, plus .github/skills and .github/instructions — and follow the architecture, the three token layers, primitives vs compounds, and the coding conventions. Then install dependencies, build all previews, start the local server, and open the M365 Copilot Playground in my browser. When you’re done, tell me in plain, non-technical language what you just set up and what the playground is, then suggest my next step from the Start Experimenting guide (creating my first experiment)."
When it’s done, the M365 Copilot Playground opens in your browser — that’s your sign everything worked. Want to double-check? Compare it with the live GitHub Pages version.
2
Start your experiment and make a change An experiment is simply your own copy of any starting point — a shell, a flow prototype, or a single component — so you can change anything without touching the original. We’ll start from the One Copilot Shell. This one prompt creates your experiment and makes a small, visible change, so you can watch the whole loop click into place.
"Create a new flow exploration called 'myExperiment' by copying the One Copilot Shell (preview/src/oneCopilotShell.ts), then change its greeting heading to 'Hello World'. Build it and open it in the browser."
Open it from the link the agent gives you, or find it on the Prototypes page. See “Hello World”? You just made your first change. If not, ask the AI which file it edited and confirm it’s your experiment.
Building your design
3
Build your design This is the fun part. Just describe what you want in plain language, and the AI edits your experiment, rebuilds, and shows you the result. Ask it to reuse existing components instead of writing new CSS, paste a Figma link to pull in real colors and layout, and keep going by telling it what to tweak next.
"Add a banner below the chat input with connected app icons for M365, Jira, and GitHub."
"Here's my Figma design: [paste URL]. Implement it as a new overlay in myExperiment."
Tips for better results • Scope work to your file — say it once: “Only edit myExperiment.ts.”
• Be specific and reference existing components by name (browse the Design System Tokens page).
• Built something reusable? Ask the AI to add it back as a component (token file, preview, catalog entry).
• ~94 Fluent + app-logo icons are bundled — ask “What icons are available?” or drop in a new one.
• If something looks broken, open DevTools (F12) → Console and paste any errors back — preview JS fails silently.
• Share anytime: “Share my experiment and give me a link.”
Share Your Experiment Get a live, shareable link for your prototype in seconds. The AI creates a fork, pushes your code, and gives you a URL.

Contributing back
4
Contribute to the community Built something useful? Share it back so others can use it too. The AI handles branching, committing, and PR creation — no git knowledge needed. Add your prototype to the Prototypes page:
"Raise a PR to add my experiment to the main prototypes page, then tell me in plain language what happens next."
Contribute a reusable component:
"I've built a notification toast in myExperiment. Add it as a new component to the design system with a token file, preview, and catalog entry."
A maintainer reviews your PR, may suggest changes, and merges it — then it’s available to everyone using the playground.
